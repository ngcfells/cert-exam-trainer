# Chunk 11: SecAI+ (CY0-001) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add CompTIA SecAI+ (CY0-001) as a second exam with verified metadata, its official acronym list, and at least 500 original MCQs and 80 original PBQs, without changing how Data+ behaves.

**Architecture:** First, the code that still assumes one exam learns about several. A small `BANKS` table maps each exam code to its folder and id prefix. The shipped-bank checks move into a shared helper that each exam's `bank.test.ts` calls. Dev tools and scripts take `--exam`. Then `src/banks/secai/` is filled one domain slice per session, using the same draft → two reviewers → approve pipeline as chunk 8. Targets are locked at the end.

**Tech Stack:** TypeScript, React 18, Zod, Vite 5 (`import.meta.glob`), Vitest, Playwright + axe, Claude subagents (drafting and review), local Ollama (acronym expansion only).

**Spec:** `docs/superpowers/specs/2026-10-30-comptia-exam-trainer-design.md` (§5, §8, §12, §13 item 11). Pipeline precedent: `docs/superpowers/plans/2026-10-30-chunk8-dataplus-bank.md`.

## Verified exam facts (checked 2026-10-31)

Source: <https://www.comptia.org/en-us/certifications/secai/> and the public CompTIA SecAI+ CY0-001 V1 Exam Objectives **Document Version 4.0** (© 2025). Version 1.1 also circulates. It has the same 15 objective titles, but v4.0 adds federated learning, backdoor and trojan attacks, the MCP server, differential privacy, awareness training and shadow IT/AI, and it is the only version that fills in the test details. **Use v4.0.**

- Code `CY0-001`, version `1`, name `CompTIA SecAI+`, launched 2026-02-17, retirement about 3 years after launch (no date given).
- At most 60 questions, 60 minutes, passing score 600 (100–900); multiple choice and performance-based.
- Domains: 1 Basic AI Concepts Related to Cybersecurity **17**; 2 Securing AI Systems **40**; 3 AI-assisted Security **24**; 4 AI Governance, Risk, and Compliance **19**.
- Objectives (copy the titles verbatim from v4.0): 1.1–1.3, 2.1–2.6, 3.1–3.3, 4.1–4.3 (15 in all).
- Official acronym list: 63 entries, as printed in v4.0 (for example `CI/CD`, `PCI DSS`, `SOC 2`, `IaC`, `IdP`, `DoS`, `DDoS`, `MLOps`, `OAuth`). Note `IP` = Intellectual Property and `SOC` = Security Operations Center on this exam.

## Global Constraints

- Every bundled item is original, written from the public objectives and the drafter's own knowledge.
- **Reference decks (owner decision 2026-10-31).** The six CompTIA instructor slide decks in `_WorkingData/SecAIPlus/` may be used **as reference and supporting documentation only**: to see which topics an objective covers, how deep to go, and to check facts. Never copy their wording, examples, questions, scenarios or diagrams, and never paraphrase a slide into an item. Drafters and reviewers get the deck text for their objective as extracted notes (Task 4a), never the `.pptx` files or a `_WorkingData` path. Every draft must pass the overlap check (no 8-word run shared with the deck text).
- The rest of `_WorkingData/` (Data+ practice questions, screenshots, dumps) stays off limits. Take objective text from the public v4.0 PDF.
- Do not commit the objectives PDF (CompTIA forbids redistributing it). `docs/sources/CY0-001.md` records where each value came from, as `DA0-002.md` does.
- Ids: `cy1-<objective with dot→dash>-<type short>-<nnn>`, for example `cy1-2-6-mcq-014` or `cy1-2-2-config-003`. Data+ keeps `da2-`.
- Targets per exam: ≥ 500 approved MCQs, ≥ 80 approved PBQs, ≥ 10 of each of the 8 templates, every objective at its `objectiveQuotas` minimum. For CY0-001 that is 29 MCQ + 5 PBQ per domain-1 objective, 34 + 6 per domain-2 objective, 40 + 7 per domain-3 objective, and 32 + 6 per domain-4 objective (507 MCQ and 90 PBQ in all).
- An item is `approved` only after both reviewers pass it (the security reviewer answers the item without seeing the key and must match it; the copywriter raises no unresolved flag).
- Subagent models (owner rule): Sonnet for drafting, security review, editing and re-review; Haiku for copywriter checks; Opus only for the final whole-branch review.
- Content runs one domain slice per session: after each slice, commit, update `HANDOFF.md`, and stop so the owner can `/clear`.
- Data+ behaviour, bank and e2e results do not change. Accessibility: axe shows no serious or critical violations.
- Branch `chunk11-secai`. Do not merge to `main` or deploy until Task 9; a half-filled exam must not go live.
- No GitHub Actions or Git LFS. Inline multi-line `node -e` fails silently in Bash here, so write a script file instead. Fix every review finding, minors included.

## Review Focus

1. **Stale facts in a fast-moving field.** OWASP renumbered and merged its LLM Top 10 entries between 2023 and 2025, so a key like "LLM07 is insecure plug-in design" goes wrong when the list is revised. Expect no item to key on a list position or a year. Pinned in Task 2 (`noListPositions`: no `LLM\d{2}`, `ML\d{2}` or `A\d{2}:` token in any item text) and in the brief in Task 5.
2. **Compound and mixed-case official terms.** If `CI/CD`, `PCI DSS` and `SOC 2` are stored as printed, the token check sees `CI`, `CD`, `DSS` and calls them unlisted. Expect a token to count as covered when it is one of the `/`- or space-separated parts of a listed term. Pinned in Task 3 (`acronymCovered`).
3. **A second exam breaks tests that assumed one.** `bank.spec.ts` clicks `/start mock exam/i` and reads `.first()` count, which become ambiguous with two exams. Expect every e2e and unit test to name its exam. Pinned in Tasks 1 and 6.
4. **The Learn button opens an empty screen.** SecAI+ has no lessons. Expect Home to hide Learn for an exam with no lessons. Pinned in Task 1.
5. **Deck wording leaks into items.** A drafter who reads a slide tends to reuse its phrasing or its example scenario. Expect no item to share an 8-word run with the deck text after case and punctuation are normalized. Pinned in Task 4a (`sharedRuns`) and run on every draft in Task 7. (The review tool writing to the wrong exam's folder is also pinned, in Task 1.)

### Task 4a: Deck reference notes and the overlap check

**Files:**
- Create: `scripts/deck-text.py`, `src/content/overlap.ts` (+ `overlap.test.ts`)
- Modify: `src/content/index.ts` (export), `scripts/check-drafts.ts`

**Interfaces:**
- Produces: `scripts/deck-text.py <deck.pptx>... --out <dir>`. It uses only the standard library (`zipfile`, `xml.etree`), so run it with `python -I`. It writes one `<deck>.txt` per deck: each slide's `<a:t>` text and its speaker notes (`ppt/notesSlides`), in slide order, under a `## Slide <n>` heading. Output goes to `_WorkingData/SecAIPlus/notes/` (git-ignored).
- Produces: `sharedRuns(text: string, reference: string, n = 8): string[]`. Both texts are lower-cased, punctuation is turned into spaces, and whitespace is collapsed. It returns each distinct `n`-word run that appears in both, in the order first seen in `text`.
- Produces: `check-drafts --ref <dir>`, which reads every `.txt` in `<dir>` and reports any item where `sharedRuns(questionText(q), ref)` is not empty, counting each one as a problem.
